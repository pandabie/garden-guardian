## บริบทที่ต้องรู้ก่อนตอบทุกครั้ง

- โปรเจกต์นี้คือ "สมองส่วนมองเห็นและตัดสินใจ" ของหุ่นยนต์กำจัดวัชพืช
- ตัวหุ่นคือ **หุ่นเตี้ยทรงกลมไถลบนพื้นแบบเครื่องดูดฝุ่น ไม่ใช่ gantry**
  กล้องอยู่ต่ำใกล้พื้น มองเฉียงจากมุมต่ำ ไม่ใช่ก้มลงจากด้านบน
  เอกสารหรือบันทึกความจำเก่าที่ยังพูดถึง gantry / home switch / ราง X-Y คือของเก่า
  **ให้ยึด `docs/DECISIONS.md` ฉบับล่าสุดเสมอ**
- ขอบเขตปัจจุบัน: **Phase 1 และ Phase 2 เท่านั้น**
  - Phase 1 = แยกพืช + ตรรกะ `protect` / `removal_candidate` / `review`
  - Phase 2 = ground-plane homography แปลงพิกเซลเป็นเซนติเมตร
  - Phase 3–5 (coverage map, edge deployment, ฐานเคลื่อนที่จริง) อยู่ใน roadmap แต่ยังไม่ลงมือ
- สวนจริงอยู่ที่ Nova Scotia ประเทศแคนาดา
- หลักการตั้งต้นของโปรเจกต์คือ **inverted detection** — สอนให้รู้จักเฉพาะสิ่งที่ต้องปกป้อง
  ไม่ใช่พยายามรู้จักวัชพืชทุกชนิดในโลก

## วิธีสื่อสารกับเจ้าของโปรเจกต์

- ตอบเป็นภาษาไทย
- ศัพท์เทคนิคทุกคำที่ใช้ครั้งแรก ต้องอธิบายว่าแปลว่าอะไร **ในบริบทของโปรเจกต์นี้**
  ไม่ใช่คำนิยามทั่วไปจากตำรา
- อธิบายทีละขั้น บอกเหตุผลและความเสี่ยงเสมอ ไม่ใช่บอกแค่ว่าให้ทำอะไร
- **ห้ามเลือกแทน** ในเรื่องที่เป็นข้อเท็จจริงของสวนจริง เช่น ชนิดพืชที่ปลูก
  ชนิดวัชพืชเป้าหมาย ขนาดพื้นที่ งบประมาณ ตารางเวลา
  → ให้เสนอตัวเลือกพร้อมข้อดีข้อเสียและเกณฑ์ตัดสิน แล้วถามก่อน
- ถ้าไม่รู้ให้บอกว่าไม่รู้ ห้ามเดาแล้วเขียนให้อ่านเหมือนรู้
- เมื่อเสนอตัวเลข (ความสูง มุม จำนวนรูป threshold) ต้องบอกด้วยว่าตัวเลขนั้นมาจากไหน
  และจะรู้ได้ยังไงว่าผิด

# กฎบันทึกปัญหา

> **ส่วนที่สำคัญที่สุดของไฟล์นี้**

ปลายทางเดียว: **`docs/PROBLEMS_TH.md`**

บันทึกนี้จะถูกนำไปใช้นำเสนอใน portfolio ดังนั้นทุก entry ต้องอ่านรู้เรื่อง
สำหรับคนที่ไม่เคยเห็นโปรเจกต์นี้มาก่อน

## เมื่อไรต้องบันทึก

บันทึกเมื่อเข้าข้อใดข้อหนึ่ง

1. สิ่งที่วางแผนไว้ทำไม่ได้จริง และต้องเปลี่ยนวิธี
2. เจอข้อจำกัดที่แก้ไม่ได้ ต้องยอมรับแล้วออกแบบรอบมัน
3. เจอความเสี่ยงที่ยังไม่เกิด แต่ถ้าไม่ระวังจะเกิดแน่
4. ต้องตัดสินใจทั้งที่ข้อมูลยังไม่ครบ
5. พบว่าเอกสาร โค้ด หรือค่า config ขัดกันเอง

## เมื่อไรไม่ต้องบันทึก

- พิมพ์ผิด หรือ error ที่แก้จบในขั้นตอนเดียวและไม่เปลี่ยนแผน
- คำถามเพื่อความชัดเจนที่ตอบแล้วจบ ไม่ได้เปลี่ยนทิศทาง
- งานที่สำเร็จตามแผนตั้งแต่ครั้งแรก

**เกณฑ์ตัดสินง่าย ๆ:** ถ้าเล่าให้คนอื่นฟังแล้วเขาได้เรียนรู้อะไรบางอย่าง = บันทึก

## รูปแบบ entry

```markdown
### P-xx — <หัวข้อสั้น ๆ>

- **พบเมื่อ:** YYYY-MM-DD
- **หมวด:** ชุดข้อมูล | ฮาร์ดแวร์ | ซอฟต์แวร์ | เอกสาร | ความปลอดภัย
- **ปัญหาคืออะไร:** อธิบายให้คนนอกโปรเจกต์อ่านรู้เรื่อง
- **ทำไมถึงเป็นปัญหา:** ผลกระทบถ้าปล่อยไว้
  (ห้ามข้ามข้อนี้ — เป็นข้อที่ทำให้บันทึกใช้กับ portfolio ได้)
- **สถานะ:** แก้แล้ว | ยอมรับเป็นข้อจำกัด | ยังเปิดอยู่ | รอข้อมูล
- **วิธีแก้ / เหตุผลที่ยอมรับ:** อธิบายว่าแก้ยังไงและทำไมถึงเลือกวิธีนั้น
  **ถ้ายังไม่มีวิธีแก้ ให้เขียนว่า "ยังไม่มี"** ห้ามแต่งวิธีแก้ที่ยังไม่ได้ลองจริง
- **ปลดล็อกเมื่อ:** (เฉพาะสถานะ ยังเปิดอยู่ / รอข้อมูล)
  ต้องรู้อะไรหรือมีอะไรก่อนถึงจะแก้ได้
```

## กฎการจัดการเลขและประวัติ

- เลข `P-xx` เรียงต่อเนื่อง **ห้ามใช้ซ้ำ ห้ามเรียงใหม่ ห้ามเติมเลขแทรก**
- **ห้ามลบ entry ที่แก้แล้ว** ให้เปลี่ยนสถานะเป็น "แก้แล้ว" เท่านั้น
  เพราะประวัติของปัญหาคือตัวเนื้อหาที่ portfolio ต้องใช้ ไม่ใช่แค่ผลลัพธ์สุดท้าย
- ถ้าต้องแก้ entry เดิม ให้ **ต่อท้าย** ด้วยบรรทัด `> อัปเดต YYYY-MM-DD: ...`
  ห้ามเขียนทับข้อความเดิม
- คำถามที่รอคำตอบจากเจ้าของโปรเจกต์ ใช้รหัส `Q-xx` เก็บในหัวข้อแยกท้ายไฟล์
  พอได้คำตอบแล้วให้ทำเครื่องหมายว่าตอบแล้วพร้อมวันที่ **ห้ามลบ**
- ทุกครั้งที่เพิ่มหรือเปลี่ยนสถานะ entry ต้องอัปเดตตาราง "สรุปสถานะ" ที่หัวไฟล์ด้วย

## กฎท้ายทุกการสนทนา

จบทุกคำตอบด้วยหัวข้อ **"ปัญหารอบนี้"** ระบุเฉพาะ `P-xx` / `Q-xx` ที่
**เพิ่มใหม่หรือเปลี่ยนสถานะ** ในรอบนั้น — ไม่ต้องพิมพ์ทั้งไฟล์ซ้ำ
ถ้ารอบนั้นไม่มีอะไรเปลี่ยน ให้เขียนว่า "ไม่มี"

# ข้อห้ามถาวร

1. **ห้ามแก้ `src/detect.py` และ `src/policy.py`** ถ้าไม่ได้รับอนุญาตชัดเจนเป็นรายครั้ง
2. **ห้ามแก้ไฟล์ใด ๆ ก่อนสรุปให้เห็นและได้รับอนุมัติ** — คุยให้จบก่อนเสมอ
3. ชื่อคลาสใน `data/data.yaml`, `config/garden.yaml` และไฟล์ label
   ต้องตรงกันทุกตัวอักษร แก้ที่หนึ่งต้องแก้ให้ครบทุกที่ในคราวเดียว (ดู P-12)
4. กฎความปลอดภัยห้ามผ่อนทุกข้อ
   - `actuation_authorized: false` ในผลลัพธ์ทุกครั้ง
   - บริเวณที่ไม่มีกรอบ **ไม่ถือว่าเป็นวัชพืช** แต่แปลว่า "ระบบไม่พบอะไร"
   - เขตกันชนรอบพืชปลูกห้ามตัดทิ้ง
   - `removal_candidate` ต้องผ่านทั้งเกณฑ์ความมั่นใจสูง และไม่อยู่ในเขตกันชน
