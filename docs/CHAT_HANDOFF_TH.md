# Context สำหรับคุยต่อใน ChatGPT — Garden Guardian

อัปเดตล่าสุด: 2026-08-05

## ผู้ใช้และวิธีช่วยที่เหมาะสม

ผู้ใช้กำลังเรียนรู้เรื่อง AI และหุ่นยนต์ ยังไม่ถนัดศัพท์เทคนิค กรุณาอธิบายเป็นภาษาไทย
แบบค่อยเป็นค่อยไป พร้อมบอกเหตุผลและความเสี่ยง ไม่ควรสมมติว่าผู้ใช้รู้วิธีเตรียม dataset,
เทรนโมเดล หรือเชื่อมฮาร์ดแวร์อยู่แล้ว

## เป้าหมายของโปรเจกต์

Garden Guardian จะเป็นสมองของหุ่นยนต์ดูแลสวนและกำจัดวัชพืช ตัวหุ่นที่วางไว้คือ
หุ่นเตี้ยทรงกลมที่ไถลไปบนพื้นเองแบบเครื่องดูดฝุ่น วิ่งอิสระบนสนามหญ้า ไม่ได้ยึดติดกับ
โครงหรือรางใด ๆ เริ่มจากระบบมองเห็นด้วย YOLOv8 แล้วค่อยเพิ่มการแปลงพิกเซลเป็นระยะจริง
บนพื้น แผนที่พื้นที่ที่ไถไปแล้ว อุปกรณ์ประมวลผลปลายทาง และหัวกำจัดวัชพืชในอนาคต

**ขอบเขตของงานรอบนี้: Phase 1 และ Phase 2 เท่านั้น** คือสมองส่วนแยกแยะพืชกับตรรกะ
ตัดสินใจ และการแปลงพิกเซลเป็นเซนติเมตรด้วย homography ส่วน Phase 3–5 อยู่ใน roadmap
แต่ยังไม่ลงมือ ไม่ต้องชวนผู้ใช้ไปทำ phase หลังก่อนที่สองอันแรกจะเสร็จ

หลักการตัดสินใจปัจจุบัน:

- พืชปลูกที่รู้จัก → `protect`
- วัชพืชเป้าหมายที่รู้จัก มีความมั่นใจสูง และอยู่ห่างพืชปลูก → `removal_candidate`
- คลาสที่ไม่ได้ตั้งค่า ความมั่นใจต่ำ หรืออยู่ใกล้พืชปลูก → `review`
- บริเวณที่โมเดลตรวจไม่พบอะไร → ไม่ดำเนินการ

`removal_candidate` เป็นเพียงคำแนะนำจากภาพ ไม่ใช่คำสั่งเปิดหัวตัดหรือหัวพ่น

## สิ่งที่ทำแล้วใน repository

- `src/detect.py` ตรวจภาพ วาดกรอบตามสถานะ และสร้าง `runs/observe/decisions.json`
- `src/policy.py` มีกฎความปลอดภัยและเขตกันชนรอบพืชปลูก
- `config/garden.yaml` แยกพืชปลูกกับวัชพืชเป้าหมายและตั้ง threshold
- `data/data.yaml` มีตัวอย่างพืช `tomato`, `basil`, `lettuce` และวัชพืช
  `dandelion`, `crabgrass`
- `src/ground_plane.py` เป็นโครง Phase 2 สำหรับ homography ยังไม่ได้ต่อกับ `detect.py`
- `docs/GETTING_STARTED_TH.md` เป็นคู่มือเริ่มต้นภาษาไทย
- `docs/DECISIONS.md` บันทึกการตัดสินใจสำคัญของโปรเจกต์
- `notebooks/01_train.ipynb` ปรับให้ฝึกทั้งพืชปลูกและวัชพืชเป้าหมาย
- `tests/test_policy.py` มีชุดทดสอบกฎความปลอดภัย 6 กรณี และผ่านทั้งหมด

ชื่อพืชและวัชพืชทั้งหมดใน config ยังเป็นตัวอย่าง ต้องเปลี่ยนตามสวนจริงก่อนตีกรอบรูป

## สิ่งที่ยังไม่มี

- ยังไม่มี dataset รูปจริง
- ยังไม่มีน้ำหนักโมเดลที่เทรนแล้ว
- เครื่องยังไม่ได้ติดตั้ง Ultralytics และ OpenCV ครบ จึงยังไม่ได้ทดสอบภาพจริงแบบ end-to-end
- ยังไม่มี ground-plane calibration จึงยังแปลง pixel เป็นเซนติเมตรบนพื้นไม่ได้
  (`src/ground_plane.py` เป็นเพียงโครงของ Phase 2 ยังไม่ได้ต่อกับ `detect.py`)
- ยังไม่มีวิธีให้หุ่นรู้ตำแหน่งตัวเอง (localization) และยังไม่มี coverage map
- ยังไม่มีการควบคุมมอเตอร์ ล้อ หรือการวางแผนเส้นทาง
- ยังไม่ควรเชื่อมผลลัพธ์เข้ากับหัวตัดหรือหัวพ่น

## แนวคิดระบบพิกัด

### หุ่นเคลื่อนที่ ไม่มีจุดอ้างอิงตายตัว

หุ่นตัวนี้ไถลไปบนพื้นเองแบบเครื่องดูดฝุ่น ไม่ได้ยึดกับโครงหรือราง จึงไม่มีจุด `(0,0)`
ที่ตรึงอยู่กับสวนให้วัดระยะเทียบได้ ทุกครั้งที่หุ่นขยับ กล้องก็ขยับตาม พิกัดที่ได้จากภาพ
จึงเป็นพิกัด "เทียบกับตัวหุ่น ณ วินาทีนั้น" เท่านั้น ไม่ใช่พิกัดของสวน

ผลที่ตามมาคือหุ่นต้อง **ประมาณตำแหน่งตัวเองตลอดเวลา** ถ้าไม่รู้ว่าตอนนี้ตัวเองอยู่ตรงไหน
ในสวน ต่อให้ตรวจเจอวัชพืชแม่นแค่ไหน ก็ยังบอกไม่ได้ว่าวัชพืชต้นนั้นอยู่ตรงไหนของสวน
และกลับไปหาอีกครั้งไม่ได้

### ระดับที่ 1 — ground-plane homography (Phase 2)

ขั้นแรกที่ทำได้จริงและไม่ต้องรู้ตำแหน่งตัวเอง คือแปลงพิกเซลในภาพให้เป็นเซนติเมตร
บนพื้นราบตรงหน้าหุ่น วิธีคือวางจุดอ้างอิง 4 จุดบนพื้นที่เรารู้ระยะจริงระหว่างกัน
ถ่ายรูปด้วยกล้องตัวเดียวกันที่มุมและความสูงเดียวกับที่จะติดบนหุ่น แล้วคำนวณ
homography matrix เพื่อใช้แปลงกลับ

ได้ผลลัพธ์เป็นคำตอบแบบ "วัชพืชต้นนี้อยู่หน้าหุ่น 32 ซม. เยื้องซ้าย 11 ซม."
ซึ่งเพียงพอสำหรับตัดสินใจเฉพาะเฟรม แต่ยังไม่ใช่พิกัดของสวน โครงเริ่มต้นอยู่ที่
`src/ground_plane.py`

ข้อจำกัดที่ต้องจำ: homography ใช้ได้เฉพาะกับสิ่งที่อยู่ **บนระนาบพื้น** เท่านั้น
พืชที่สูงขึ้นมาจากพื้นจะคลาดเคลื่อน และถ้าพื้นเอียงหรือเป็นเนิน ค่าที่ได้จะเพี้ยน

### ระดับที่ 2 — coverage map

เป้าหมายคือให้หุ่นจำได้ว่า "ไถตรงไหนไปแล้วบ้าง" เพื่อไม่วนซ้ำที่เดิมจนแบตหมด
และไม่ปล่อยให้มีมุมที่ไม่เคยผ่านเลย แนวคิดคือแบ่งสวนเป็นตาราง แล้วทำเครื่องหมาย
ช่องที่กล้องเคยเห็นและตรวจไปแล้ว พร้อมเวลาที่ตรวจ

แต่ coverage map จะทำงานได้ก็ต่อเมื่อรู้ตำแหน่งตัวเองเท่านั้น ถ้าตำแหน่งเพี้ยน
แผนที่ก็เพี้ยนตาม จึงต้องแก้เรื่องด้านล่างก่อน

### ปัญหาหลักที่ยังไม่แก้ — localization

**นี่คือปัญหาที่ยังไม่มีคำตอบ และยังไม่ได้เลือกวิธีแก้**

วิธีพื้นฐานที่สุดคือ odometry คือนับรอบล้อแล้วคำนวณย้อนว่าเคลื่อนไปเท่าไร แต่บนสนามหญ้า
วิธีนี้เพี้ยนเร็วมาก เพราะ:

- ล้อลื่นบนหญ้าเปียกหรือน้ำค้าง ล้อหมุนแต่ตัวหุ่นไม่ได้ไปไกลเท่าที่นับได้
- หญ้าสูงต่ำไม่เท่ากัน ทำให้ระยะต่อรอบล้อไม่คงที่
- พื้นสวนไม่เรียบ มีเนินและหลุม
- ความคลาดเคลื่อนสะสมไปเรื่อย ๆ ยิ่งวิ่งนานยิ่งเพี้ยนมาก และไม่มีอะไรมาแก้ให้กลับมาตรง

ทางเลือกที่ยังต้องศึกษาต่อ (ยังไม่ตัดสินใจ): visual odometry จากกล้อง, ArUco marker
ปักตามมุมสวนเป็นจุดอ้างอิง, IMU ช่วยวัดการหมุน, RTK-GPS, หรือ SLAM เต็มรูปแบบ
แต่ละทางมีต้นทุนและความยากต่างกันมาก

**ข้อดีข้อเสียของแต่ละทาง และเงื่อนไขที่ต้องรู้ก่อนเลือก อยู่ในหัวข้อ
"Open problem: localization" ใน [DECISIONS.md](DECISIONS.md)**

สำคัญ: อย่าเพิ่งเลือกวิธีให้ผู้ใช้ และอย่าเชียร์ทางใดทางหนึ่ง ตอนนี้ยังไม่มีกล้อง
ไม่มีตัวหุ่น และยังไม่รู้ขนาดสวนจริง การเลือกตอนนี้คือการเดา ผู้ใช้ตั้งใจให้เรื่องนี้
เป็นโจทย์ที่เปิดอยู่ ถ้าผู้ใช้ถามเรื่องนี้ ให้ช่วยหาคำตอบของ 8 ข้อในเช็กลิสต์ท้ายหัวข้อนั้นก่อน

จนกว่าจะแก้เรื่องนี้ได้ ผลลัพธ์ทุกชิ้นใช้ได้เฉพาะกับเฟรมที่คำนวณมันออกมาเท่านั้น

### หลักการความปลอดภัยที่ยังคงเดิมทุกข้อ

การเปลี่ยนตัวหุ่นไม่ได้เปลี่ยนกฎความปลอดภัยเลย ทุกข้อต่อไปนี้ยังใช้เหมือนเดิม:

- พืชปลูกที่รู้จัก → `protect` ห้ามแตะ
- วัชพืชเป้าหมายที่มั่นใจสูงและอยู่ห่างพืชปลูก → `removal_candidate` ซึ่งเป็น
  **คำแนะนำ** ไม่ใช่คำสั่งเปิดหัวตัด
- ไม่แน่ใจ ไม่รู้จัก หรืออยู่ใกล้พืชปลูก → `review` ให้คนตรวจ
- เขตกันชนรอบพืชปลูกยังต้องมี และเมื่อหุ่นเคลื่อนที่ได้ ยิ่งต้องเผื่อระยะมากขึ้น
  เพราะตำแหน่งตัวหุ่นเองก็มีความคลาดเคลื่อน
- บริเวณที่ไม่มีกรอบ = ระบบไม่พบอะไร ไม่ใช่ "เป็นวัชพืช"
- `actuation_authorized: false` ยังต้องติดอยู่ในผลลัพธ์ทุกครั้ง
- ยังต้องมี hardware safety controller และปุ่มหยุดฉุกเฉินก่อนต่อกับกลไกจริง

## ขั้นถัดไปที่ควรทำ

ถามผู้ใช้ก่อนว่าในสวนจริงปลูกพืชอะไร และต้องการกำจัดวัชพืชชนิดใด จากนั้นช่วยแก้
`data/data.yaml` และ `config/garden.yaml` ให้ตรงกัน แล้ววางแผนถ่ายรูปและตีกรอบ dataset
ไม่ควรเลือกชนิดพืชแทนผู้ใช้ เพราะตัวอย่างปัจจุบันอาจไม่ตรงกับสวนจริง

## Prompt สำหรับเริ่ม Chat ใหม่

### ต้องแนบไฟล์อะไรบ้าง

ชุดขั้นต่ำ 3 ไฟล์ แค่นี้เข้าใจ scope ได้ครบ:

| ไฟล์ | ให้อะไร |
|---|---|
| `docs/CHAT_HANDOFF_TH.md` | ไฟล์นี้ — ตัวหุ่น, scope, สถานะปัจจุบัน, ระบบพิกัด, กฎความปลอดภัย |
| `docs/DECISIONS.md` | เหตุผลเบื้องหลัง และโจทย์ localization ที่ยังเปิดอยู่ |
| `README.md` | roadmap 5 phase และโครงสร้างโปรเจกต์ |

แนบเพิ่มตามเรื่องที่จะคุย:

- กฎตัดสินใจหรือ threshold → `config/garden.yaml` และ `src/policy.py`
- ground-plane homography (Phase 2) → `src/ground_plane.py`
- การเตรียม dataset → `docs/GETTING_STARTED_TH.md`

อีกทางคือส่งลิงก์ repo <https://github.com/pandabie/garden-guardian> แล้วบอกให้อ่าน
โฟลเดอร์ `docs/` แต่วิธีนี้ขึ้นกับว่า chat นั้นเปิด web search ไว้หรือไม่
ถ้าอยากให้ชัวร์ ให้แนบไฟล์ตรง ๆ

> ตัวหุ่นเป็นหุ่นเตี้ยทรงกลมที่ไถลไปบนพื้นเองแบบเครื่องดูดฝุ่น วิ่งอิสระบนสนามหญ้า

### ถ้าอยากคุยต่อเรื่องใดเรื่องหนึ่งโดยเฉพาะ
